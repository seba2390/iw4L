# Black Ops 3 — fidelity ledger

Rule: Black Ops 3 matches run on Black Ops 3's own rules and data; no other
game's behaviour stands in. Its gameplay rules live in its compiled scripts,
so the path to a match is running those scripts: a loader and VM for Black
Ops 3's compiled script format and the builtins those scripts call. IW4L
writes no Black Ops 3 gameplay rule of its own. A rule that is not recovered
is an `unknown!` in `game_t7`, listed here with its id; `cargo xtask boundary`
refuses an id that is missing here.

**Owner decision (2026-10-10), no exceptions:** nothing of another game stands
in for Black Ops 3 — not Modern Warfare 2's (or any other game's) movement,
weapons or any other rule, not even temporarily. Unlike Black Ops 2, Black Ops
3 gets no lent rules in `session/src/games.rs`; what is not recovered from
Black Ops 3's own files stays Unknown.

Severity: **V** visible, **A** audible, **G** gameplay, **I** invisible.

## Open

- [ ] **G** Black Ops 3's compiled scripts run on IW4L's script VM: `gsc_t7`
      decodes each function with a table of which instruction each 16-bit
      opcode value stands for (`gsc_t7/src/opcodes.rs`, generated) and
      translates it into IW4L's script IR; calls link by namespace and name
      hash, builtins by name (`gsc_t7/src/names.rs`, generated). The opcode
      table is the game's own: `BlackOps3.exe` dispatches a value with bit 13
      clear through a table of 0x2000 handlers, read from the running game's
      decrypted image; a value is named by its handler, and a handler by the
      functions whose compiled code matches their source in Treyarch's Black
      Ops III Mod Tools (`share/raw/scripts`) or by code compiled from known
      source with the Mod Tools' own linker. Names come from the same
      source/module pairing. 5 388 of the 8 192 values are named; the game
      rejects 2 499 as invalid, and the rest belong to instructions no
      current script uses. Shadows of Evil: 423 modules, every function
      decodes, 10 458 of 10 468 translate (the others use animation
      references, `GetAnimation`); 1 244 builtins, 293 of them without a
      known name (bound as `#hash`). *Needs:* animation references, the
      remaining builtin names, and Black Ops 3's builtins themselves.
- [ ] **G** `t7.scripts.gametypes` (`GameModes::mode`,
      `GameScripts::program`): Black Ops 3 modes other than Classic zombies
      (`zclassic`) on a zombies map are refused. *Needs:* Black Ops 3's
      rules for those modes.
- [ ] **G** `t7.movement.player`, `t7.weapons.state_machine`,
      `t7.match.last_stand` (`ModeRules`): Black Ops 3's player movement,
      weapon state machine and down rule are not known. *Needs:* those rules.
- [ ] **V** `t7.hud.code_hud` (`HudRules::code_hud`): Black Ops 3's
      code-drawn HUD is not known. *Needs:* its HUD rules.
- [ ] **V/G** A Black Ops 3 match is refused at install: "No drawable
      world" — the map's world (geometry, collision, spawns) is not decoded.
      *Needs:* the layouts of Black Ops 3's world assets.
- [ ] **V** `t7.vision.shellshock` (`GameVision::shellshock`): Black Ops 3's
      shellshock files and screen rules are not known. *Needs:* Black Ops 3's
      shellshock format and screen rules.
- [ ] **V** `t7.hud.menu_font` (`GameMenus::font`): which font a Black Ops 3
      menu names is not known. *Needs:* Black Ops 3's menu font table.
- [ ] **V** `t7.hud.menu_layout` (`GameMenus::layout`): how Black Ops 3's
      menus place items is not known. *Needs:* Black Ops 3's menu rules.

### Not read yet (outside `game_t7`)

- [ ] **V/A/G** Black Ops 3 zones are not decoded: the asset lane for a game
      IW4L does not read (`assets/src/lane/mod.rs`, `UnreadLane`) reports every
      capability missing, and a Black Ops 3 map loads as an empty world with
      that gap; only its compiled script modules and its map entities (`map_ents`,
      the entity text, handed to the scripts as for the other games) are read
      (see below). Its materials compile no pass, its sounds, localized strings,
      weapon names, viewmodel hands and ADS overlay rule are not read.

### What IW4L chose for Black Ops 3 (not read from the game)

- [ ] **I** Which zones a map's scripts come from (`fastfile_t7`,
      `script_zones`): `core_patch`, then for zombies maps `zm_levelcommon`
      and `zm_patch`, then the map and `<map>_patch`; a later zone's module
      replaces an earlier one of the same name. Black Ops 3's own zone list is
      not read. (The map zones carry no scripts; `zm_zod.ff` has 44 967 assets
      and none is a script.)
- [ ] **I** A Black Ops 3 map still prepares the runtime's composed common
      set (Modern Warfare 2's `common_mp` and the other games' shared banks)
      before it is refused. Nothing of it reaches a Black Ops 3 match today;
      a playable one must not take it.

- [ ] **G** Classic zombies mode values are IW4L's (`game_t7`,
      `ZOMBIES_MODE`): play starts on the level notify
      `all_players_connected` (a flag Black Ops 3's `_zm.gsc` sets), players
      join `allies`, the scripts spawn them, the engine imposes no limit,
      the host waits for the lobby.
- [ ] **G** Script start order is IW4L's (`game_t7`): every `autoexec`
      function, modules in include order (a module after the modules it
      includes), then the gametype's `main`, then the map's `main`. Black Ops
      3's own order of code callbacks is not read.
- [ ] **G** Class instances (`gsc_t7`, `New`): an instance carries a copy of
      its class's method table (`__vtable` of `classes.<class>[0]`); Black
      Ops 3 links the instance to its class description and looks methods up
      there. Method calls resolve the same way; a script that changed a
      class's method table after making instances would see the difference.
- [ ] **I** `world` and `classes` are objects IW4L makes the first time a
      script names them; how long Black Ops 3 keeps `world` across maps is
      not read.
- [ ] **G** `waitrealtime` waits like `wait` (IW4L's match time does not
      scale).
- [ ] **G** `FirstArrayKey`/`NextArrayKey` walk an array in IW4L's key
      order (integers, then strings); Black Ops 3's iteration order is not
      known.
